# 启动与验收步骤

## 一、前置条件

- 已安装 Docker 与 Docker Compose（`docker compose version` 可正常输出）；
- 已注册 DeepSeek 开放平台并创建 API Key（见《操作手册》第 1-3 章）；
- 80 端口未被占用（或修改 `.env` 中的 `NGINX_PORT`）。

## 二、启动步骤

```bash
cd ai-assistant

# 1. 生成并配置环境变量
cp .env.example .env
# 用 openssl rand -hex 32 重新生成 JWT_SECRET 与 ENCRYPT_KEY
# 修改 DB_PASSWORD、ADMIN_PASSWORD
vi .env

# 2. 构建并启动
docker compose up -d

# 3. 查看状态（postgres 健康检查通过后 backend 才启动，首次构建需几分钟）
docker compose ps
docker compose logs -f backend
```

服务清单：

| 服务 | 说明 |
| --- | --- |
| nginx | 唯一对外入口（默认 80 端口），反代前端与后端 |
| frontend | Nginx 托管的 Vue3 SPA |
| backend | Spring Boot API（8080，仅内网） |
| postgres | PostgreSQL 15，首次启动自动执行 init.sql 建表 |
| redis | 预留（当前限流为内存实现） |

## 三、验收清单

- [ ] 浏览器打开 `http://localhost` 能看到登录页，标题为「铸语 PromptForge」，页脚为「铸语 PromptForge · © 城荣杰月」。

### 6. 越权与安全

- [ ] 连续输错密码 5 次，账号 + IP 被锁定，提示稍后再试；
- [ ] 后端日志中检索不到 API Key 明文与 JWT。

## 四、常见问题

| 现象 | 处理 |
| --- | --- |
| backend 反复重启 | `docker compose logs backend` 查看报错，通常是 `.env` 缺 `JWT_SECRET/ENCRYPT_KEY` 或数据库密码不一致 |
| 80 端口被占 | 修改 `.env` 的 `NGINX_PORT` 后 `docker compose up -d` |
| 首次构建依赖下载慢 | 配置 Docker 镜像加速与 npm 镜像 |
| 想完全重置数据 | `docker compose down -v` 后重启（会删除全部数据） |

## 五、本地开发模式（不用 Docker）

```bash
# 后端（需本地 PostgreSQL，并先执行 deploy/postgres/init.sql）
export JWT_SECRET=$(openssl rand -hex 32)
export ENCRYPT_KEY=$(openssl rand -hex 32)
mvn spring-boot:run

# 前端（5173 端口，/api 自动代理到 8080）
cd frontend && npm install && npm run dev
```
